# SHIPLAB — 바이브 코딩 첫 배포 연습실 (v4)

ChatGPT/Codex 스타일 AI 코딩 → GitHub 자동 푸시 → Vercel 배포 과정을 체험하는 비공식 교육용 시뮬레이터입니다.

## 처음 시작하는 학습자를 위한 설명

각 단계에서 다음 내용을 큰 글씨로 보여 줍니다.

- **왜 이 과정이 필요할까요?**
- **이 과정은 언제 하나요?** 최초 1회인지, 새 프로젝트마다인지, 수정할 때마다인지
- **다음부터는 어떻게 하나요?**
- **용어 이해하기**: 프롬프트, 푸시, 커밋, 저장소, Import, 배포 등

처음 방문하면 `AI는 만든다 → GitHub는 보관한다 → Vercel은 공개한다` 역할 안내를 보여 줍니다. 역할 설명은 접거나 펼칠 수 있습니다.

## 따라 하기

1. AI에게 만들고 싶은 홈페이지를 문장으로 설명합니다.
2. 코딩 에이전트와 GitHub를 **모의 로그인·권한 승인**으로 연결합니다.
3. AI가 GitHub 저장소를 만들고 커밋·푸시하는 과정을 체험합니다.
4. GitHub Code 화면에서 올라간 파일과 커밋을 확인합니다.
5. Vercel에 모의 로그인하고 GitHub 저장소에 대한 접근 범위를 설정합니다.
6. GitHub 저장소를 Import하고 정적 HTML 사이트로 모의 배포합니다.
7. 완성 뒤 **코드 수정하고 재배포**를 선택하면 기존 저장소·연동 정보를 재사용해 AI 재푸시 → **Vercel 자동 재배포**를 체험합니다.

## 한 번만 하는 일과 반복하는 일

| 활동 | 실제 서비스에서의 일반적인 반복 주기 |
| --- | --- |
| GitHub 또는 Vercel 계정 만들기 | 계정당 처음 1회 |
| 로그인 | 로그인 세션이 유지되면 생략되지만, 만료 시 다시 필요 |
| 코딩 에이전트와 GitHub 연동 권한 승인 | 연결할 때 주로 1회. 권한/계정이 바뀌면 재승인 가능 |
| Vercel GitHub 앱 연결 | 계정·조직 연결 시 주로 1회. 새로운 저장소의 허용 범위는 추가 설정 가능 |
| 새 GitHub 저장소 만들기 | 새로운 프로젝트 시작 시 |
| Vercel 프로젝트 Import·설정 | 프로젝트당 최초 배포 시 |
| AI 수정 요청과 코드 커밋·푸시 | 수정할 때마다 |
| 연결된 Vercel 재배포 | 새 푸시가 생기면 자동 배포 가능 |

## 안전 및 한계

**웹앱 자체는 실제 GitHub 저장소를 통해 Vercel에 배포할 수 있지만, 화면 속 로그인·권한 승인·파일 푸시·배포는 모두 모의실습입니다.** 실제 비밀번호나 OAuth 토큰을 입력하지 않습니다. AI의 저장소 푸시 기능은 ChatGPT의 단순한 GitHub 조회 연결이 아니라 Codex 같은 코딩 에이전트의 사용 사례를 교육용으로 단순화한 것입니다. 실제 서비스 UI와 인증 흐름은 변경될 수 있습니다.

## 개발·배포

단일 정적 HTML 파일 `index.html`을 프로젝트 루트에 두고 Vercel의 GitHub Import를 이용합니다. Framework Preset: Other, Build Command: 사용 안 함.
